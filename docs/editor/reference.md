### Embedded languages during edits

A `LineTokenizer` may provide `prepare(text)` to load embedded grammars named by edited text. It resolves to `true` when a load can invalidate earlier states; `stale()` then reports the rebuild once. Shiki tokenizers recognize Markdown and MDX fence info and `lang` attributes in Vue, Svelte and Astro. Ordinary prose does not load fence languages. Concurrent documents share each language load.

The editor checks declarations in edited lines 200 ms after the last edit, with one preparation running at a time. Undo, redo and external edits use the same path. A buffer above 64 KiB triggers one scan of the current document. After a grammar rebuild, coloring starts at the first line while previous colors stay visible. External `setLineTokens` providers pause preparation; clearing the provider schedules a full scan. Theme changes and disposal ignore late preparation results.

### Worker request lifecycle

`@adecore/editor/worker-client` exports `createWorkerRequestClient`, `WorkerRequestError`, `WorkerRequestErrorKind`, `WorkerRequestPort`, `WorkerRequestOptions` and `WorkerRequestClient`. It owns one active request and one pending request; the newest request supersedes both. Requests are posted in a microtask. A deadline starts before posting and includes worker startup; timeout terminates the worker. Load failures before its first message remain unavailable. `release()` frees the worker and lets the client restart; `dispose()` is final.

`request(inputFactory, deadline?, validate?)` allocates a monotone id after validation. Protocol adapters supply response validation, deterministic failures that keep the worker alive, optional message preparation and a stop hook for snapshot caches. A `{ type: 'ready' }` reply marks successful startup without completing a request. Use a separate client for independently cancellable work. The search client uses this lifecycle without changing its public protocol.
